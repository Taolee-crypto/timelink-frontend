# DAILY FREE 음악 시간상품·결제 결과 화면

2026-10-26 · 음악 구독 주문 백엔드 #230 후속

## 사용자 연결

지갑의 ‘음악 시간 구독’ → `/music-subscriptions.html` → TL-1~TL-24 선택 → 시간·요금·조건 확인 → 서버 주문 준비 → 구독 목적의 Toss 결제창 → `/payment-success.html` 구독 전용 확인.

초기 정식 판매는 비활성이다. 운영자가 시험 모드와 일치하는 공개키·서버키를 구성한 경우에만 시험결제 버튼을 제공한다. live 키를 복사하거나 프론트에서 결제 모드를 임의 변경하지 않는다. 운영 환경변수는 이 변경으로 수정하지 않는다.

## 화면 구성

- 서버가 반환한 24개 상품만 표시. 조회 실패 시 임의 가격·예시 잔액을 표시하지 않는다.
- 하루 포함시간과 월 요금 초안, 초과 1초=1TL, 초기 1개월·자동 반복 결제 없음 안내.
- 선택·이용조건 확인 후 주문 생성. 가격은 브라우저에서 제출하지 않고 서버 주문 응답을 다시 대조한다.
- 회원 번호별 세션 주문 요청키를 유지해 통신 중단·결제창 취소 후 같은 주문으로 재시도한다.
- 미해결 주문이 있으면 다른 상품 결제를 막고 기존 주문 확인을 안내한다. 만료 주문도 임의 새 주문으로 우회하지 않는다.
- 로그인 사용자의 등록 자격과 일일 잔여시간 조회.
- 통신·권한 오류에서는 저장된 표시값으로 결제를 진행하지 않는다.

## 결제 목적 분리

| 주문 | 승인 API | 결과 |
| --- | --- | --- |
| v5music_ | /api/payment/v5/music/confirm | 구독 영수증·자격·구매 기여. 지갑 TL 발행 없음 |
| v5promo_ | /api/payment/v5/premium/toss/confirm | 기존 홍보 결제 처리 유지 |
| 기존 충전 주문 | /api/payment/toss/confirm | 기존 TL 충전 처리 유지 |

음악 구독 결과 화면은 `tl_user`의 지갑 잔액을 수정하지 않는다. 시험 승인과 실제 구독 승인을 구분해서 표시한다. 로그인 정보가 없으면 TL 충전 화면으로 결제 파라미터를 넘기지 않고, 로그인 후 같은 결과 화면에서 다시 확인할 수 있도록 한다. 실패·취소 화면은 음악 구독 화면으로 돌아간다.

## 공개 결제 설정

신규 백엔드 공개 응답은 `testCheckoutEnabled`, 시험 모드에 일치하는 `clientKey`, `billingTimezone`, `billingPeriod`, `autoRenew`를 제공한다. 공개키만 제공하며 비밀키는 응답에 포함하지 않는다. 정식 checkoutEnabled는 false를 유지한다.

기존 백엔드 버전에서는 신규 필드가 없으므로 결제 버튼이 비활성으로 남는다. 화면을 먼저 배포해도 일반 TL 충전 경로로 대체하지 않는다.

## 검증

실제 Chromium에서 24개 상품, 정식 판매 비활성, 서버 주문 금액 대조, 시험 SDK 목적·콜백, 재시도 요청키 유지, 미해결 주문의 등급 변경 제한, 구독 승인 후 지갑 불변, 로그인 복구, 실패 복귀, 기존 TL 충전 회귀, 통신 실패 후 표시 제거, 모바일 레이아웃을 확인한다. API·SDK는 시험용 대체 응답으로 검증하며 실제 결제하지 않는다.

실제 플레이어의 구독 사용 경로, 곡별 정산, 현금 재무 보고, 취소·환불·약관과 운영 E2E를 마친 뒤 정식 판매를 활성화해야 한다.
