## 0. 문서의 적용 범위와 상태
이 문서는 대화에서 확정한 사업 원칙, GitHub 기본 브랜치에서 확인한 코드 기본값, 새로 제안하는 실행 규칙을 구분한 통합 운영 명세다. 코드·DB 설정·계약·은행 지급을 변경하지 않았다.
- **확정**: 사용자가 지정한 정책. 실제 구현 완료라는 뜻은 아니다.
- **코드 기본값**: 읽은 코드에 있는 숫자. 운영 DB 저장값·현재 계약·실제 지급 결과와 같다고 단정하지 않는다.
- **제안**: 운영을 위해 작성한 규칙. 승인 전 실제 과금·보상에 적용하지 않는다.
- **미정**: 수치·범위·책임 확정이 필요하다.
상충 시 현재 대화의 사용자 명시 정책을 우선하되 기존 지급 의무·계약을 자동 삭제하지 않는다. 새 시행일·정책 버전과 이행 경로를 마련한다.
TLMALL은 유통업체 입점형 온라인 몰이다. 쿠팡에도 공급하는 업체가 들어온다는 사업 정의이며 쿠팡 제휴·자동 연동·재고 확보를 의미하지 않는다. TimeLink가 모든 상품을 직매입한다는 이전 해석은 폐기한다.

## 1. 경제 원칙
1. 외부에서 들어온 상품·서비스·광고·마케팅 재원을 확인하고 그 재원에서 지급·정산한다. TLC 가격 상승이나 신규 가입비로 반복 운영 손실을 메우는 구조를 전제하지 않는다.
2. 음악 권리자 배분은 해당 음악 이용 재원에서 처리한다. 이미 플랫폼에 귀속된 몫을 음악 권리자에게 다시 같은 비율로 나누지 않는다.
3. 플랫폼 몫에서는 운영비와 DJ·소비자·영업매니저 등 활동 보상 예산을 운영한다. 해당 서비스의 파트너 배분과 추가 활동 보상은 서로 다른 항목으로 표시한다.
4. 일반 이용·상점 마케팅·몰 보상·창작자 수익이 같은 TL로 표시돼도 출처, 부담자, 사용·환전 조건을 보존한다.
5. TL_P 현금 환전, TL_P 상품 사용, TL/TLC 교환, 기여 기반 TLC 신규 채굴은 서로 다른 사건이다. 교환은 기존 자산 이전이며 추가 채굴과 같은 것으로 기록하지 않는다.
6. 음악·몰·상점의 실제 소비와 서비스 이용에서 매출을 확보한다. 구매가 늘수록 보상 차감 후 이익이 남는지 확인한다. 성장·TLC 가격·환금 유동성을 보장하지 않는다.

창작자가 직접 듣거나 테스트하는 세션, 체험, 재생 실패, 실제 음악이 아닌 멘트·뉴스 구간의 과금/보상은 상품별로 명시한다. 확인하지 않은 무료 범위를 임의로 만들지 않는다.

## 4. 음악·권리자 보상 세칙
### 4.1 음악 배분 원칙
해당 음악 이용에 배정된 TL 재원×70%를 권리자 몫으로,30%를 플랫폼 몫으로 구분한다. 미사용 유료 충전·상품 거래 전체·상점 마케팅 예치금 전부에70%를 적용하지 않는다.
공동 작곡·작사·편곡·음반 등 분배 대상자는 검증된 권리·합의 지분에 따라 권리자 재원 안에서 배분하며 합계가100%인지 확인한다. 연락처 인증만으로 권리 보유를 확정하지 않는다.
권리자가 확인되지 않은 금액은 해당 권리자 몫으로 보류하고 업로더 또는 플랫폼의 자유 수익으로 전환하지 않는다. 권리자 확인·이용허락·지급은 별도 절차다.
광고/선물 원천의 음악 사용에서 생기는 보상을 현금화 가능한 수익으로 전환할지는 확보된 재원과 계약을 확인한다. 기존 코드가 출처 제한을 보존하는 부분을 전체 현금 수익으로 임의 전환하지 않는다.

### 4.2 TILO 예시
검증 음악방송1,000초 → 총300TL → 권리자210TL, 플랫폼90TL.
국가별 승인 현지 자정에 일일 정산하고 월간 합계는 현지 월 기준으로 관리한다. 미국 등 복수 시간대 국가는 정산 시간대를 별도 정책으로 지정한다.
방송 프로그램 실행시간이 아닌 실제 음악 송출 증거로 계산한다. 동일 방송 이벤트를 사용자 접속 수나 매장 수만큼 중복 지급하지 않는다. 별도 권리계약 과금 방식이 있다면 함께 검토한다.
TILO 플랫폼30% 내부 배분은 외부 현금 매출이 아니다. 자체 부담 방송과 외부 유료 음악 사용은 경제 보고서에서 구분한다.

### 4.3 기존 TILO 발전기여금
기존 코드에는 권리자별 월 TILO 총 배분에 대한 구간별 공제 산식이 있다.
| 월 총 권리자 TILO 보상 구간 | 해당 구간분 공제율 |
| --- | ---: |
| 0~100,000TL | 0% |
| 100,000 초과~500,000TL | 5% |
| 500,000 초과~2,000,000TL | 10% |
| 2,000,000 초과~5,000,000TL | 15% |
| 5,000,000TL 초과 | 20% |
모든 금액에 최종 구간율을 일괄 적용하지 않는다. 월200,000TL이면100,000×0%+100,000×5%=5,000TL이다.
이는 국가의 세금이 아니라 사전에 합의·고지해야 할 계약상 플랫폼 발전기여금이다. 현금 세금과 별도 표시한다. 계산 코드 존재와 전체 지급 경로의 활성화는 구분한다.

### 4.4 창작자 현금 환전
권리자70% 보상 전체에 대해 일반 청취자50% 자격 기준을 적용하지 않는다. verified PoC에 따른 별도 환전 가능 비율을 적용한다는 원칙이다.
코드의 초기 제안은 PoC0.1~1미만10%,1~2미만20%,2~3미만40%,3~4미만60%,4~5 80%다. 관리자가 확정한 운영 환전표가 아니며, 새100점 채굴표와 같은 척도로 취급하지 않는다.
환전 가능 비율과 TL/현금 환산 단가는 다르다. 환전 불가 나머지 잔액의 소멸·사용·추후 자격 향상 시 처리도 미정이므로 임의 소멸시키지 않는다.

## 5. 스토어·매니저·DJ 세칙
### 5.1 가입 선물과 파트너 배분
스토어 선물은 총100,000TL이다. 선물 사용분에서 매니저·DJ의 새 유료 보수를 발생시키지 않는다. 여러 매장 등록 시 회원당/매장당 선물 기준은 미정이다.
유료 서비스비10,000TL이면 매니저·DJ 공동 재원5,000TL, 플랫폼5,000TL이다. 내부25/25안이면 매니저2,500·DJ2,500이나 최종 수치는 별도 승인한다.
원화 지급액은 TL수량 자체로 확정하지 않고 실제 계약·승인 평가액·수취/세무 확인을 연결한다.

### 5.2 과금 모델 충돌
코드에는50,000TL/30일 이용료 기본값과0.5TL/초 스토어 종량 기본값이 함께 존재한다. 이를 같은 이용에 자동 중복 부과하지 않는다. 실제 활성 경로와 저장값은 운영 검증이 필요하다.
참고: 종량0.5TL/초로 하루12시간×30일이면648,000TL이다.50,000TL 정액과 같은 가격이라고 설명하면 안 된다.
운영 제안은 상품을 다음 둘 중 하나로 명확히 선택하는 것이다.
- 정액권: 포함 기간·시간/서비스 범위를 명시하고 포함 이용을 추가 종량 청구하지 않는다.
- 종량: 실제 검증 이용량만 차감한다.30일 단위 값은 예산·패키지로 명시하고 사용 조건을 별도로 정한다.
혼합 요금이라면 포함량·초과량·초과단가·동의 시점을 명시해야 한다. 이번 문서로 새 요금 모델을 확정하지 않는다.

### 5.3 방송 선택·운영
스토어 회원은 계약 매니저와 연결된 DJ 방송을 선택하고 시간대별로 예약한다. 해당 시간은 중앙방송을 대체하며 같은 시간에 양쪽 과금이 겹치지 않도록 설계한다.
사용자 지정 DJ 하루 방송 상한은6시간이다. 세션 분할·계정 역할 중복으로 회피하지 않도록 일 합산하고 국가별 기준일·공동방송 산정을 정한다. 이 문서에서 상한 구현·배포까지 검증한 것은 아니다.
상점주 요청으로 담당 매니저를 바꾸면 이후 거래부터 적용하고 과거 거래 배분은 보존한다. DJ 미선택·매니저 미배정 시50%공동 재원의 귀속은 미정이므로 플랫폼이 임의 흡수하지 않는다.
종료·불출석·방송 장애·중복 예약의 취소·대체·환불은 계약별 규칙으로 명시한다.

## 6. 상점 마케팅 TL_P
확인된 실제 소비5,000KRW×1%=50KRW상당=50TL_P. 이는 이 한국 예시의 적립 환산 기준이며 모든 국가·자산의 현금 교환율 확정이 아니다.
실행 제안:
1. 상점주 보상 재원을 확보하고 결제 사실과 취소 상태를 확인한다.
2. 원거래별1회 지급하며 고객 TL_P와 상점 부담액을 같은 거래로 기록한다.
3. 즉시 사용 가능한 정책을 유지하되 예산 부족 시 미지급을 성공으로 표시하거나 무재원 발행하지 않는다. 사전에 적립 가능 여부를 안내한다.
4. 부분 취소는 동일 기준액으로 재계산한 차액을 정정한다. 이미 소비한 보상의 회수는 계약과 사용자 통지를 갖춘 별도 정정/채무로 다룬다.
5. 배송비·부가세·할인·TL사용분 포함 여부와 소수점은 확정 필요다. 기존 고객 혜택을 조용히 줄이지 않는다.
상점 부담금에 별도 플랫폼 수수료를 받을지는 미정이다.1% 적립액을 자동으로 플랫폼 매출로 잡지 않는다.

## 7. TLMALL 상품·유통마진·보상
### 7.1 거래와 책임
회원 주문 → 결제 승인 → 공급업체 이행 → 구매 확정/취소 확인 → 공급업체 정산·플랫폼 마진·보상 확정이라는 상태를 제안한다.
판매계약 주체, 공급가·유통마진, 재고 소유, 배송비, 반품·하자·CS, 세금계산서, 정산 주기, 보상 부담, 손실 귀속을 입점 계약에 명시한다. 모든 책임이 자동 공급업체에 있다는 뜻은 아니다.
총거래액·공급업체 정산금·플랫폼 경제적 수익을 분리한다. 법정 회계상 총액/순액 매출 표시는 실제 본인/대리인 판단에 따라 별도 결정한다.

### 7.2 TL_P 적립
구매 보상은 전부 TL_P이며 현금 환전·실물 구매가 가능하다. 적립률을 매출액에 일률 적용해 공급업체 정산금까지 보상 재원으로 쓰지 않는다.
제안 산식:
- G = 실제 확보한 유통마진.
- C = 해당 거래에서 플랫폼이 부담하는 결제·운영·반품손실 등 비용. 이번 신규 TL_P 보상 비용은 아직 포함하지 않는다.
- A = max(0,G-C).
- 신규 TL_P 보상 비용 상한 = A×보상 배정률.
- 플랫폼에 남는 금액 = A-신규 TL_P 보상 비용.
보상 배정률30%는 초기 예시 제안이지 확정값이 아니다. 예산은 TL_P 전액의 최대 약정 이행 부담과 관련 비용을 충당하도록 보수적으로 확보한다. 회원이 음악에 사용할 것이라는 기대만으로 환전 준비금을 축소하지 않는다.
설명용 한국 주문100,000원: 공급업체85,000, 플랫폼 마진15,000, 플랫폼 거래비용3,000 → 보상 전12,000. 그30%=3,600원을 보상 예산으로 배정하면8,400원이 남는다. 예시에서만1TL_P당 준비금1원으로 가정할 때3,600TL_P이며, 실제 전역 환전율을 확정하는 것이 아니다.

### 7.3 상품 구매에서 TL 사용
기존 확정 한도: min(구매당10,000KRW상당,상품가격50%,사용가능 적격잔액). 이 상한을 모든 상품에 무재원 할인할 의무 또는 TLC 결제 한도로 확대 해석하지 않는다.
혼합 결제에서는 현금/유료충전/마케팅보상/몰보상 재원을 각각 추적해 공급업체에 지급할 금액이 충족되는지 확인한다.
이미 지급된 TL_P 사용분은 해당 발행 시 확보한 정산 재원을 소비하는 것이므로 매번 같은 비용을 새로 중복 계산하지 않는다. 유료 TL의 기존 수금과 신규 외부 현금도 구분한다.
외부 재원 없는 무한 재적립 방지 제안: 신규 구매 보상 기준을 새 현금 결제 순액과 계약상 추가 확보 마진에서 산정한다. TL사용분 재적립은 추가 재원이 확인된 상품/캠페인에 한한다. 아직 확정한 사용자 정책은 아니므로 시행 전 조건을 승인·고지한다.
몰 적립과 오프라인1%의 동시 적용은 캠페인별 재원 확보·허용 여부를 정한다. 같은 원거래의 단순 중복 수집으로 이중 지급하지 않는다.

### 7.4 적립 시점과 환불
상점1%의 즉시 사용과 TLMALL 구매 보상의 확정 시점을 혼동하지 않는다. 몰은 결제 시 적립예정 표시, 구매 확정 시 사용가능 전환을 제안한다. 즉시 사용을 제공하려면 반품·미배송 보상 회수 재원을 별도 마련한다.
주문 취소 시 공급업체 정산·마진·TL사용 반환·신규 적립 취소를 함께 연결한다. 일부 품목 취소는 주문 전체가 아닌 해당 품목별 재계산을 한다.

## 9. TLC 채굴
### 확정 원칙
회원 유형에 관계없이 공통 회원 가입 시 기본 참여 자격을 얻는다. 실제 채굴은 검증된 플랫폼 기여 기준을 충족해야 한다. 상점주도 포함한다. 보유TL·지출·가입비만으로 자동 채굴하지 않는다.
생태계 참여·채굴 확대에 따라 더 까다로운 기준으로 공급 속도를 조절하려는 방향이다. 신규가입자 수만으로 난이도를 올려 다계정 공격을 허용하지 않는다.

### 제안 단계
최근90일 기여를100점으로 환산하는 안: 콘텐츠/서비스30,실제이용20,수익기여25,운영15,신뢰10. 기존PoC지수0.1~5와 별도 숫자이므로 검증 이벤트의 정규화·연결 규칙을 마련한다. 별도 중복 점수 원장 대신 기존 체계를 확장한다.
10점 개시 제안에 대해 사용자가 ‘처음10%’를 검토했으나 숫자 최종 확정으로 간주하지 않는다. 기여도10%와 채굴 지급률10%는 다르다.
| 누적 채굴 구간 제안 | 최소 최근 기여점수 | 전체 수량 상한 배수 |
| --- | ---: | ---: |
| 0~B미만 | 10 | 1.00 |
| B~2B미만 | 15 | 0.85 |
| 2B~3B미만 | 20 | 0.70 |

B는 승인한 초기 채굴 구간이며 선발행 총량이 아니다. B·기준 누적량·일한도·개인집중 상한은 미정이다. 사용자 수·활동·실제 소비수요도 함께 검토하고 예고된 정책 버전으로 적용한다.
현재 기존 코드의 월TL_P소비×0.08×PoC·플랜B2배·월소비30%상한은 이 새 공통 채굴 정책과 같지 않다. 두 방식을 동시에 지급하지 않는다.
교환은 기존 잔액 이전, 신규채굴은 별도 승인 발행으로 원장을 분리한다.

### 발행 예산
이익·보호현금 기준으로 총 보상 예산을 제한하는 것은 운영 제안이다. 구체적10/20/30%·운영예비비3~6개월은 앞선 제안 문서의 시험값이며 확정 수치가 아니다.
TLC 평가단가는 내부 위험/보상 예산 산정값과 실제 교환 견적을 구분한다. 시장가격 상승을 영업이익으로 잡거나 가격 하락 불가를 약속하지 않는다.
초기 이익이 없어도 필요하면 보호자금과 분리한 유한한 출시 실험 예산을 승인할 수 있다. 한도·기간·중단조건을 명시하고 기존 지급 의무를 취소하지 않는다.
기여점수는 지급 확정 TLC와 다르다. 점수만 생겼다고 현금/토큰 지급 채무가 확정됐다고 표시하지 않는다.

현재 일반 환전 코드: 구매실적이 지급 이력의50%이상인지 심사, 구매원금 누적 한도,기본최소1,000TL_P,플랜A5%/B3%수수료. 이는 코드 기본 규칙이며 최신 몰 보상의 현금 환전 가능 정책을 구현하지 못한다. 회원에게 구매를 강요해 환전 자격을 얻도록 만드는 방식으로 임의 보완하지 않는다.
출처별 환전 가능 잔액 산출→견적과 수수료 고지→신청액잠금→관리자/지급 검토→실제지급증빙→완료 또는 원잠금반환으로 처리한다.
국가: KR/KRW,JP/JPY,US/USD,CN/CNY,TH/THB,VN/VND. 각국 과금·보상 단가와 환율 효력·정산시간대·수수료·반올림·세무·지급경로를 구분한다. 모든 나라에서1TL=1현지통화로 두지 않는다.
국경 간 상품 주문은 배송·관세·통화 비용과 책임을 계약에 명시한다. 한 국가의 고객 보호자금으로 다른 국가 보상을 임의 충당하지 않는다.

## 11. 지급·정정·세금·원장 공통 규칙
- 원거래ID,회원/국가/법인,자산,원천재원,부담자,정책버전,시행일,금액/단위,세금/수수료,수취인,확정/취소/지급 상태를 기록한다.
- 재시도에는 같은 중복방지키를 사용하고 의미가 바뀌면 충돌을 반환한다. 지급·예산 차감·수취인 적립을 원자적으로 처리한다.
- 예상적립·확정적립·사용가능·예약/잠금·환전대기·지급완료를 구분한다.
- 기존 거래 삭제로 맞추지 않고 취소/정정 연결을 남긴다. 상품 부분환불·방송 장애·정산 취소·은행 지급 실패를 원거래와 연결한다.
- V5 원장에서 TL소수4자리 정밀도와 TLC별 최소단위를 명시한다. 반올림/절사 시점은 항목별 고정하고 잔여분 귀속을 기록한다.
- 지급 수수료,국가세금,플랫폼 발전기여금은 다른 항목이다. 역할명만으로 세율을 일괄 적용하지 않는다. 실제 국내/해외·개인/사업자·소득 종류에 맞춰 확인한다.
- 수익 발생,지급가능 확정,은행지급,세금 신고/납부를 분리하고 증빙을 연결한다. 실제 세무 확정은 기존 정산·세금 문서와 국가별 검토를 따른다.
- 은행 지급증빙 등록은 자동 송금 실행이 아니다. 관리자 수동 승인과 변경 이력을 유지한다.
