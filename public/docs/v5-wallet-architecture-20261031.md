# TimeLink V5 지갑 구조 설계 — 확정 기준 (2026-10-31)

## 범위와 완료 정의
이 문서는 지갑 **구조 설계**의 확정 기준이다. 구현 상태, CI 통과, 운영 계정 검증, 기존 원장 복구를 100%라고 주장하지 않는다. 초기화는 별도 승인·백업·리허설·감사기록을 거쳐야 하며 본 문서는 초기화 실행을 허가하지 않는다.

## 1. 자산과 보관 구분
- TL: 사용자에게 표시·지급·차감·교환하는 모든 TL은 **정수**이다. 기존 원장 호환 단위는 10,000 atoms = 1 TL이며 신규 TL 거래는 10,000 atoms의 정수배만 허용한다. 0.3 등의 비율 계산에서 발생하는 잔여 atoms는 정책적으로 명시된 별도 누적·반올림·정산 절차로 처리하고 사용자 TL 잔액을 소수로 만들지 않는다. 계정별 wallet_paid(TL_P), wallet_ad(TL_A), wallet_bonus(TL_B)를 분리한다. 화면의 사용 가능 총 TL은 세 버킷의 사용 가능 잔액 합계와 항상 일치해야 한다.
- TL_P: 유상 구매분. 구매 후 법정 환불 기간이 지나면 정책에 따라 TL_B로 전환하되, 환불 가능성·결제 상태·잠금과 전환 거래를 원장에 별도로 남긴다. 전환은 총 TL을 늘리지 않는 동일 자산 버킷 간 이동이다.
- TL_A: 광고 기능은 중단. 기존 TL_A 잔액 및 감사 이력은 보존하며 신규 광고 적립은 차단한다.
- TL_B: 비환금성 TL. 보상·전환 등 발생 원인과 원천 자금 구분을 거래 메타데이터로 기록한다. 유상 판매 수익에서 지급되는 권리자 보상은 별도의 정산채무·현금 지급 규칙을 적용하며 임의로 TL_B로 대체하지 않는다.
- TLC: TL과 다른 자산. 별도 자릿수(현재 원장 표시 10^9 atoms/TLC)와 계정·전환 승인·지급 원장을 유지한다. TILO는 방송 서비스이며 TLC의 자산명이 아니다.
- TIME FREE: TL 잔액이 아닌 독립적인 시간 권리. granted_ms, used_ms, 상태, 결제·주문 식별자, 만료 조건을 관리한다. 초과 사용 및 음수 잔여시간을 차단한다. TIME FREE 청취 자체에 TL 보상은 지급하지 않는다.

## 2. 이중기입과 원장 불변식
- 모든 경제 이벤트는 고유 idempotency_key를 갖는 하나의 원자적 트랜잭션으로 기록한다. 재시도는 기존 결과를 반환하며 이중 반영하지 않는다.
- 동일 거래·동일 자산의 모든 원장 항목 합계는 0이어야 한다. 발행·소각·프로모션도 플랫폼 발행/비용/준비금 대응 계정을 통해 양변을 기록한다. 단일 항목만 있는 거래는 원칙적으로 차단한다.
- TL의 정수 정책은 지갑·교환풀·음악 청취·방송·기여 보상·정산·TLMALL·관리자 화면과 모든 백엔드 지급/차감 API에 공통 적용한다. 비율별 반올림·잔여 처리 방식은 수익 배분 정책으로 별도 확정하며 임의로 소수 TL을 지급하지 않는다.
- 금액 계산은 정수 atoms를 사용하며 부동소수 반올림으로 잔액을 갱신하지 않는다. 모든 합계는 안전한 정수 범위 및 DB 정수 범위 검증을 거친다.
- 사용자 사용 가능 잔액은 계정별 원장 합계에서 계산한다. 캐시·레거시 필드는 표시 기준의 진실 공급원이 아니며 불일치 시 조용히 덮어쓰지 않고 진단한다.
- 거래 상태(준비/승인/완료/취소/환불), 원인 이벤트, 사용자·사업자·권리자·플랫폼 계정, 환율/가격정책 버전, 국가·현지시간, 감사 주체를 추적한다.
- 잠금·예약·환불 가능 잔액은 사용 가능 잔액과 분리하고 중복 사용을 막는다. 음수 잔액은 정책적으로 허용된 명시적 계정 외에는 거부한다.

## 3. 기능별 원장 연결
1. 구매·충전: 결제 승인과 유상 TL 발행을 주문·결제 ID로 연결. 실패/중복/환불/차지백에 대한 역거래를 원자적으로 처리한다.
2. 청취: 실제 유효 재생 구간에 대해서만 정해진 사용 정책 적용. TL 소비와 권리자 70%/플랫폼 30% 분배는 거래 출처별 지급 수단·환금성을 구분한다. TIME FREE는 별도 시간 차감만 수행한다.
3. 중앙방송 TILO: 실제 송출 초를 기준으로 플랫폼 비용 부담과 70/30 권리 배분을 별도 원장에 기록. 청취자 TL을 이중 차감하지 않는다.
4. 공유플레이스 시간 구매: 시간 단위와 가격 할인을 분리하며 할인 전 명목 시간권리는 확정된 정책에 따라 발행. 결제·시간 발행·취소를 연결한다.
5. TL↔TLC 교환: 적격 잔액, 환산율, 수수료, 유동성, 국가별 규정 및 승인 상태를 확인한 뒤 양 자산 각각 이중기입한다. TL_B/TL_A를 무단 환금하지 않는다.
6. TLMALL: 구매 보상 TL의 재원과 출처를 기록. TL 사용 상한은 건당 10,000원 상당 및 상품가격의 50% 중 작은 값, 보유 적격 잔액 이하이다. 구매 취소는 보상 회수와 사용분 조정 정책을 거친다.

## 4. API와 화면 계약
- 인증된 GET /api/eco/wallet: tl_p, tl_a, tl_b, tl_total, tlc. 총액은 세 TL 버킷 합계와 일치해야 한다. 오류·누락·원장 미준비 시 추정치를 잔액으로 표시하지 않는다.
- 인증된 GET /api/v3/economy/history: limit/offset, entry_id, transaction_id, asset_code, amount_atoms, created_at, description. 페이지 중복 제거, 정렬, 사용자 소유권 및 민감정보 비노출을 검증한다.
- 인증된 GET /api/payment/v5/shareplace-time/status: time_free_remaining_ms. 실제 패스·세션·사용량 집계와 일치해야 하며 음수/비정수는 오류 처리한다.
- 로그아웃·계정 변경·토큰 만료 시 화면의 잔액·원장·시간 정보를 즉시 숨기고 오래된 응답은 폐기한다.
- 조회 API는 읽기 전용을 원칙으로 한다. 과거 데이터 마이그레이션·보정은 별도 관리자 승인 작업으로 분리한다. 현재 백엔드의 조회 시 레거시 가입 보상 reconcile 동작은 이 원칙에 맞게 개선해야 한다.

## 5. 초기화와 이관
- 초기화 전: 원장 전체 스냅샷, 결제·정산 증빙, 사용자별 잔액 및 권리자 채무를 독립 저장하고 해시·버전·승인자·시각을 기록한다.
- 과거 거래의 합계 불일치 4건을 포함한 모든 이상 거래는 원인 분류와 감사 기록을 남긴다. 단순 삭제나 임의 상쇄로 정상화하지 않는다.
- 테스트 환경에서 재현·초기화 리허설을 완료한 뒤 관리자 승인 시에만 운영 초기화. 법적·회계적 보존 대상과 실제 사용자 권리는 임의 소멸시키지 않는다.
- 새 원장의 개시 잔액은 검증된 기초잔액 이중기입으로 이관하고 기존 원장과 대사한다. 실패 시 롤백 절차를 제공한다.

## 6. 검증 완료 게이트
- 정적 계약·CI 통과, 실제 회원 인증 API 조회, 회원별 버킷 합계 대조, 모든 거래의 자산별 0합계, 원장-화면 일치, TIME FREE 패스/사용량 대조, 중복요청·환불·계정전환·권한 오류 회귀 테스트.
- 운영 검증이 완료되기 전까지 '구조 설계 100%'와 '운영 검증 100%'를 혼용하지 않는다.
