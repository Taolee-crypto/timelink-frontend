# TimeLink Admin Center 재구축 기준

## 핵심
기존 서비스·관리자 인증·작동 중인 API를 보존하면서 독립 페이지형 관리 솔루션으로 단계적 전환한다. 화면과 백엔드 API의 연결을 전수 검사한다. 재무·정산·TL 수치는 검증된 실제 원장에서만 표시한다.

## 관리자 메뉴 구조
- 통합 대시보드 / 실시간 운영
- 회원 관리: 검색, 필터, 선택, 정지/해제, 삭제 영향 검토
- 콘텐츠·TL3 권리 관리
- 재무 관리: 결제·환불·매출·TL 판매/소비
- 크리에이터·DJ·카페·인카 정산
- TL 경제·보상 정책: 7:3 정책, 관리자 수동 변경, 감사 이력·안전 한도
- 방송·광고·캠페인 운영
- 시스템: 권한·보안·로그·배포·인프라

## 확인된 결함
- /api/admin/revenue: 프론트에서 호출, 백엔드 src/routes/admin.ts에 미구현 → 404
- /api/admin/realtime: 프론트에서 호출, 동일 라우터에 미구현 → 404
- /api/admin/creators/payouts: 실제 환경에서 404; 전체 라우터 등록 확인 필요
- 비JSON 404 응답을 JSON 파싱해 추가 SyntaxError 발생
- 회원 영구 삭제 API는 안전 잠금 상태. 버튼만으로 삭제 완료 표시 금지

## 실행 단계
1. 프론트 호출 API와 백엔드 등록 경로 전수 대조, 미연결 목록 작성. 공통 인증·반응형 상단바·언어 선택·에러 상태 확립.
2. 관리자 공통 레이아웃 및 독립 페이지를 순차 구현. 기존 기능 연결 보존.
3. D1 실제 스키마와 경제 원장을 검증하여 읽기 전용 재무/실시간/정산 API 구현, 집계 수치 검산.
4. 관리자 쓰기 작업은 역할 검증·영향 미리보기·이중 확인·감사 기록·복구 방안 마련 후 개방.
5. 운영 초기 보상 룰은 관리자 수동 제어. 충분한 데이터 축적 후 자동 수익 안전 솔루션 검토.

## 출시 기준
프론트 빌드, Worker dry-run, API 계약 테스트, 관리자 인증/권한 테스트, 모바일·다국어 겹침 테스트, 실제 배포 검증을 통과해야 완료로 판단한다. 데이터 삭제·원장 변경·정산 실행은 별도 승인 없이 하지 않는다.
