## 3. 구현 상태를 구분할 때 사용할 표준

- 구현 확인: 코드에서 동작 경로가 확인됨. 운영 성공을 의미하지는 않음.
- 부분 구현: 일부 모듈 또는 API가 있으나 전체 사용자 흐름은 미확인.
- 문서상 목표: 문서에 정의되어 있으나 구현 근거가 확인되지 않음.
- 레거시: 구버전 또는 호환 경로가 코드에 남아 있음.
- 검증 필요: 권한·실제 운영 설정·배포 상태를 확인해야 함.
- 대표자 결정 대기: 기존 구현과 최신 운영 방향이 충돌하여 정책 결정이 필요함.

## 4. 보호 원칙

이 등록부는 문제를 기록하는 문서이며, 자동으로 코드를 변경하지 않는다. 보안 문제도 우선 영향 범위와 실제 운영 사용 여부를 확인한 뒤 별도 수정 계획과 테스트를 수립한다. 기존 정상 동작을 유지해야 하는 페이지와 API는 회귀 테스트 없이 변경하지 않는다.
