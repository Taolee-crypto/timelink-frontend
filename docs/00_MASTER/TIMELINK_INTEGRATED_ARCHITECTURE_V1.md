# TimeLink 통합 마스터 아키텍처 v1.0

- 작성 기준일: 2026-10-14
- 상태: 통합 설계 기준선 / 구현 전 기존 기능 대조 필수
- 적용 저장소: timelink-frontend, timelink-backend, timelink-score
- 목적: 기존 TimeLink 구현 자산을 보존하면서 공통 플랫폼과 개별 서비스의 구조를 통합한다.

## 0. 최상위 정의

TimeLink는 창작권과 디지털 파일 소유권을 존중하고, 권리자가 자신의 디지털 자산을 기술적으로 보호·관리·공유·유통·이용할 수 있도록 하는 시간 기반 디지털 자산 플랫폼이다.

TimeLink는 콘텐츠의 저작권이나 파일 소유권을 자동으로 취득하지 않는다. 업로더는 자신이 업로드하는 파일에 관한 권리 및 업로드·공유·유통 권한을 보유한다는 점에 대해 법적 책임을 부담한다. TimeLink는 업로더의 선언, 외부 발매 이력, 제출 증빙 및 기술적 파일 식별 정보를 기록하고 관리한다.

TimeLink의 모든 디지털 자산은 공통 시간·권한·보호·회계 기반을 사용한다. 자산 유형별로 제작, 표현, 재생·열람 및 소셜 상호작용은 개별화한다.

핵심 원칙:
1. 창작권과 파일 소유권은 정당한 권리자에게 있다.
2. 업로드 파일의 적법성 및 권리 보유에 대한 1차 법적 책임은 업로더에게 있다.
3. 외부 서비스 발매 이력은 추가 인증 자료이며, 그 자체로 모든 권리의 소유를 확정하지 않는다.
4. 원본 소스 파일과 보호된 TL 파일은 별도 자산 객체로 관리한다.
5. SharePlace의 공개·공유 대상은 보호된 TL 자산이다. MP3/MP4/PDF/JPEG/PNG 등 원본 파일을 공개 재생·공유하는 구조를 만들지 않는다.
6. 공통 기술은 한 번 구현하고 TL3/TL4/TLD/TLJ 및 각 서비스가 공유한다.
7. 모든 서비스 활동은 TL Economics의 통합 규칙에 연결하되, 활동량만으로 보상을 자동 확정하지 않는다.
8. 기존 정상 기능과 API 계약, 데이터 및 URL은 대조·검증 없이 제거하거나 변경하지 않는다.

## 1. 제품 구조의 큰 구분

### 1.1 공통 플랫폼 기반

공통 기반은 모든 서비스가 재사용하는 플랫폼 서비스이며, 반드시 사용자 메뉴에 각각 노출되는 것은 아니다.

- Identity & Account: 회원, 로그인, 본인 확인, 역할·권한
- Rights & Ownership Registry: 업로더 선언, 권리자·파일 소유 주장, 증빙, 외부 발매 이력, 권리 범위, 신고 및 이력
- Asset Registry: 원본 파일과 TL 파일의 식별자, 소유자, 생성 관계, 메타데이터, 버전
- Creator File Service: 업로드, 로컬 에이전트, 원본 파일 선택·보관·해시 및 TL 제작 입력
- TL Container Core: TLNK 컨테이너 공통 규격, 타입별 헤더, 무결성 및 버전 검증
- Time Authorization: 이용 권한, 세션, 허용 시간, 이용 범위, 만료 및 철회
- Content Protection & Delivery: 암호화 자산 접근, 보호된 전달, 플레이어·뷰어에 대한 권한 확인
- Usage Accounting: 사용량 측정, TL 예약·차감, 세션 및 원장 기록
- Social Core: 좋아요, 댓글, 답글, 공유, 저장, 팔로우, 신고, 알림
- Discovery & Catalog: 자산 색인, 검색, 분류, 정렬, 추천 및 공개 범위
- Payment & Wallet: 충전, 지갑, 거래 내역 및 관련 결제 연결
- TL Economics: TL, TLC, POC, 기여 판정, 보상, 정산 및 경제 정책
- Advertising Core: 광고주 캠페인, 광고 인벤토리, 광고 공급원 어댑터, 이벤트 검증, 보고 및 정산
- Integration Hub: 외부 음악 서비스·유통사·광고 네트워크 및 기타 파트너 API
- Notification & Analytics: 활동 알림, 운영 통계, 감사 로그
- Admin Control: 역할 기반 운영, 정책 버전, 심사, 신고, 감사 및 롤백

### 1.2 디지털 자산의 네 가지 동등한 유형

- TL3 — Audio: 음악, 음성 및 오디오 저작물
- TL4 — Video: 영상, 영화, 클립 및 동영상 저작물
- TLD — Document: 도서, 문서, 보고서 및 전자 출판물
- TLJ — Image / Visual: 사진, 이미지, 그래픽 및 시각 저작물

네 유형은 공통 자산 등록·권리·시간 인증·보호·이용 회계·기여 기반을 공유하지만 각 유형별 제작 흐름, 메타데이터, 뷰어·플레이어 및 상세 페이지 표현을 유지한다.

### 1.3 개별 제품·활동 영역

- SharePlace: 네 유형의 TL 자산을 발견하고 공유하는 중심 공간
- Creator: 원본 소스 파일을 선택·등록하고 보호된 TL 파일을 제작하는 도구
- My Dashboard: 개인의 자산과 플랫폼 활동을 통합하는 개인 작업 공간
- My Files: 개인이 보유·관리하는 원본 및 TL 파일 라이브러리
- My Assets / My Music: 본인이 만든·보유한·관리 권한을 가진 자산의 유형별 관리
- TimeLink Label: 음악 분야의 아티스트·음반·트랙·발행·카탈로그·유통 관리 서비스. 권리 또는 파일 소유권을 취득하지 않는다.
- Track Page: 곡별 공개 페이지이자 소셜·홍보·이용·관리의 중심
- TL방송국: 플랫폼 방송 허브
- DJ: DJ 프로필, 선곡, 방송 세트 및 관련 활동
- Cafe: 커뮤니티와 카페 공간·채널 관리
- InCar: 차량 환경의 음악 이용 및 홍보 청취 채널
- Ads: 직접 광고와 외부 광고 공급원을 함께 운영하는 광고 영역
- Score: TL3 음원 기반 악보 생성 등 선택적 음악 확장 기능

## 2. 핵심 자산·권리 모델

### 2.1 원본과 TL 파일의 관계

원본 파일과 TL 파일은 같은 파일의 두 URL이 아니라 서로 다른 자산 객체다.

- SourceAsset: 업로더가 제공한 원본 입력 파일. 기본적으로 비공개 제작·보관 자산이며 공개 SharePlace 플레이어나 공개 원본 URL로 제공하지 않는다.
- TLAsset: Creator가 만든 보호된 TLNK 컨테이너. 유형(TL3/TL4/TLD/TLJ), 버전, 헤더, 암호화·무결성 메타데이터 및 원본과의 관계를 가진다.
- Publication: TLAsset을 SharePlace 또는 다른 허용된 채널에 게시하는 별도 레코드다.
- UsageSession: 이용자, TLAsset, 이용 권한, 시간, 차감 및 세션 상태를 기록한다.

SourceAsset을 바꾸거나 제거해도 이미 발행된 TLAsset, 권리·감사 기록이 조용히 손상되지 않도록 참조 무결성과 영향 확인을 제공한다.

### 2.2 업로더 책임과 권리 확인 방식

기본 등록:
- 업로더 계정과 본인 확인 상태를 기록한다.
- 업로더가 소유 또는 적법한 이용·공유·발행 권한을 보유한다는 선언에 동의한다.
- 선언문 버전, 동의 시각, 업로더 ID, 파일 해시, 업로드 시각을 기록한다.
- 허위 선언 및 권리 침해에 대한 업로더의 법적 책임을 명시한다.

외부 발매 이력 확인:
- Spotify 등 외부 음원 서비스의 아티스트 프로필 또는 공개 발매 이력, 앨범·트랙 메타데이터, ISRC 등 식별 정보를 확인 자료로 사용할 수 있다.
- 공개 카탈로그 메타데이터 확인과 원본 음원 파일 제공 권한은 서로 다른 기능이다. 스트리밍 서비스 연결만으로 원본 파일 다운로드 권한을 전제하지 않는다.
- 외부 발매 이력은 해당 발매물과 아티스트의 연관성을 뒷받침하는 자료다. 모든 작사·작곡 저작권, 실연권, 음반제작자 권리 또는 재발행 권한을 자동 증명하지 않는다.
- 외부 계정 연결, 아티스트 프로필 확인, 트랙 식별자 및 업로드 파일 대조 결과를 기록한다.

추가 권리 증빙:
- 유통 확인서, 계약서, 권리자 동의서 등 필요한 자료를 제출할 수 있다.
- 확인 수준은 '업로더 선언', '외부 발매 이력 확인', '추가 권리 증빙 확인' 등 증빙 수준으로 표시한다.
- 증빙 수준을 법률상 권리의 우열 또는 완전한 소유권 보증으로 표현하지 않는다.

파일 무결성:
- 해시와 파일 지문은 파일 동일성·변경 여부 확인 수단이며, 단독으로 저작권이나 소유권을 증명하지 않는다.
- 창작자, 저작권자, 실연자, 음반제작자, 파일 소유 주장자, 발행·공유 권한자는 서로 다른 역할로 기록할 수 있다.
- 권리 범위와 이용 허락은 자산·지역·기간·매체·행위별로 표현할 수 있어야 한다.

### 2.3 TimeLink의 역할

TimeLink는 권리를 양도받거나 자동으로 취득하지 않는다. 기술적으로 다음을 수행한다.
- 권리자·업로더의 선언과 제출 증빙 기록
- 외부 발매 정보 연동 및 대조
- 파일 식별·무결성·버전 관리
- TL 파일 제작·발행·접근 제어
- 허용된 범위의 공유·이용·유통 기록
- 이용량, 기여 및 정산 내역의 추적
- 신고·분쟁·제한·이의제기 절차 지원

## 3. 음악 영역: TL3, Label, Album, Track

### 3.1 TimeLink Label

TimeLink Label은 전통적인 권리 인수형 레이블이 아니라 기술 기반의 음반 발행·관리·유통 지원 서비스다.

기능:
- 아티스트 프로필 및 아티스트 계정 연결
- 외부 음원 서비스·유통사 연동
- 기존 발매 정보 가져오기 및 메타데이터 매칭
- 원본 음원 등록 및 권리 선언·증빙 확인
- 싱글·EP·앨범 구성
- 커버 아트, 트랙 순서, 크레딧, 발매 설명 관리
- TL3 생성 및 발행 검증
- 발행 승인·예약·취소·버전 관리
- 음반·트랙 카탈로그
- 이용·홍보·공유 통계와 정산 내역
- 제휴 유통사 API가 지원하는 범위에서 외부 유통 요청 및 상태 동기화

TimeLink는 음원 서비스의 공개 페이지에서 원본 음원을 임의로 추출하지 않는다. 원본은 권리자가 제공하거나 정식 유통 파트너가 권한에 따라 전달해야 한다.

### 3.2 두 가지 음반 발행 경로

A. 기존 발매 음원:
1. 아티스트가 외부 서비스 계정 또는 프로필을 연결한다.
2. 기존 앨범·트랙·발매일·ISRC 등의 정보를 가져온다.
3. 아티스트와 업로드 파일의 연관성을 확인한다.
4. 업로더 책임 선언 및 필요한 발행·공유 권한 확인을 거친다.
5. 권리자가 제공한 원본 MP3와 기존 메타데이터를 대조한다.
6. 기존 발매 이력 및 식별정보를 보존하면서 TL3를 제작한다.
7. 권한이 확인된 범위에서 TimeLink 카탈로그에 발행한다.

B. 신규 창작 음원:
1. 아티스트가 원본 음원을 제공한다.
2. 권리·참여자·발행 메타데이터를 등록한다.
3. 업로더 책임 선언과 필요한 증빙을 확인한다.
4. 싱글·EP·앨범을 구성하고 TL3를 제작한다.
5. TimeLink 카탈로그에 발행한다.

기존 음원을 TL3로 패키징하는 것만으로 새 저작권이나 새 녹음물의 권리가 생기지 않는다. 기존 ISRC 등 식별정보의 유지 여부와 새 식별정보 필요성은 녹음물의 실질적 변경 및 해당 유통 규정에 따라 처리한다.

### 3.3 앨범 페이지와 트랙 페이지

Album Page:
- 앨범 커버, 제목, 아티스트, 발매일, 앨범 설명
- 트랙 목록과 트랙별 이동
- 앨범 공유 및 저장
- 발행·권리·카탈로그 정보
- 앨범 단위 홍보 및 통계

Track Page:
- 곡 하나마다 고유하고 안정적인 페이지 URL/ID를 부여한다.
- 곡의 공개 정보, TL3 재생, 아티스트, 앨범, 발매일, 작사·작곡·편곡·참여자, 가사(권한이 있는 경우), 소개와 창작 배경을 표시한다.
- 좋아요 및 취소, 좋아요 수
- 댓글, 답글, 수정·삭제 정책, 신고 및 운영 관리
- 내부 공유, 외부 공유, 링크 복사
- 내 음악/즐겨찾기에 저장
- 아티스트 팔로우
- 아티스트가 직접 게시하는 곡별 홍보 콘텐츠, 이미지 및 공지
- 청취·좋아요·댓글·공유·저장 등 활동 통계
- 권리 확인 수준, 발행 상태, 파일 및 버전 관리(권한이 있는 소유자·관리자에게만)
- 일반 방문자에게는 공개 허용된 정보와 이용 기능만 표시한다.
- 아티스트·권리자에게는 같은 페이지에 관리 도구를 추가로 표시한다. 별도 중복 페이지를 만들지 않는다.

좋아요·댓글·공유 등 소셜 활동은 Social Core를 사용한다. 이벤트 수를 그대로 POC 보상으로 간주하지 않으며 유효성·중복·자동화·부정행위 검증을 거친 기여 규칙만 경제 시스템에 전달한다.

### 3.4 악보다운로드

악보다운로드는 음악 분야의 별도 기여·확장 경로로 유지한다. TL3 기반 분석 및 악보 생성은 timelink-score 저장소의 기존 파이프라인을 재사용하고, 권리 정보와 TL 이용 권한을 준수한다. 일반 Creator의 파일 변환 기능과 혼동하지 않는다.

개인 대시보드는 로그인 후 개인 활동의 출발점이다. 음악 사용자만을 위한 화면이 아니라 TL3/TL4/TLD/TLJ 전체를 통합한다.

- 홍보 및 소셜 반응 요약

- 내 파일 열기
- 내 음악/트랙 관리
- 홍보 관리

### 4.2 My Files

개인 파일 라이브러리. 유형과 상태에 따라 필터링한다.
- 원본 입력 파일: MP3, MP4, PDF, JPEG, PNG 등
- 생성된 TL 파일: TL3, TL4, TLD, TLJ
- 제작 보조 자료: 커버, 이미지, 가사, 설명, 자막, 문서 메타데이터
- 파일 상태: 업로드 중, 원본 등록, TL 제작 중, TL 제작 완료, 발행됨, 비공개, 공유 중, 제한/검토
- 파일명, 타입, 크기, 생성일, 해시, 연결된 TL 자산, 버전 및 권한

- 삭제·교체 전에 발행물, 공유, 권리 기록 및 이용 기록에 미치는 영향을 설명하고 확인을 받는다.

### 4.3 My Assets / My Music

- My Assets는 네 자산 유형 전체의 통합 관리 화면이다.
- My Music은 아티스트가 관리하는 앨범과 트랙의 음악 전용 보기다.
- 본인이 창작한 자산, 파일 소유 자산, 관리 권한이 위임된 자산, 저장한 자산을 서로 구분한다.
- 소유, 창작, 발행, 관리, 공유 권한을 한 가지 '내 것' 상태로 뭉뚱그리지 않는다.

## 5. SharePlace와 소셜 기능

SharePlace는 TL3/TL4/TLD/TLJ를 동등하게 다루는 자산 발견·공유 공간이다.

- 자산 유형별 탐색, 검색, 장르·주제·태그·정렬·필터
- 보호된 TL 자산의 상세 페이지 연결
- 권리·발행·이용 조건에 대한 표시
- 좋아요, 댓글, 공유, 저장 등 공통 Social Core
- 추천과 인기 집계는 검증된 활동 데이터를 사용한다.
- MP3 무료 공개/재생/다운로드, 무료 발행 분기는 목표 제품 모델에 포함하지 않는다.
- 원본 파일은 공개 SharePlace 항목이 아니다.

Track Page는 음악의 곡별 소셜 페이지이고, 다른 유형은 각 유형에 맞는 Asset Detail Page를 제공한다. 공통 상호작용은 재사용하되 문서·영상·이미지에 음악 전용 필드를 강제하지 않는다.

- 방송 운영자·진행자·DJ 관리

### 6.3 Cafe

기존 Cafe/InCar 요금·배분·POC 배율은 과거 구현 기준으로 기록된 값일 수 있으므로, 실제 백엔드 계산과 거래 내역을 대조한 후에만 관리자 설정으로 활성화한다. 경제 정책을 UI 개편과 함께 임의 변경하지 않는다.

## 7. 광고 아키텍처

광고는 하나의 내부 Ad Engine과 다수의 공급원 어댑터로 구성한다.

### 7.1 광고 공급원
1. TimeLink 직접 광고: 광고주가 TimeLink에서 캠페인·소재·예산·기간·타깃·게재 위치를 관리한다.
2. 외부 광고 네트워크/API: 공급자별 승인·계약·SDK/API 정책을 준수하여 광고 인벤토리를 공급받는다.
3. 제휴·어필리에이트: 제휴 링크 및 성과 이벤트를 별도 출처로 추적한다.

### 7.2 Ad Integration Hub
- 공급자 계정 및 인증정보(서버 보안 저장)
- 공급자별 광고 요청·응답 어댑터
- 광고 소재 및 형식 정규화
- placement·targeting·eligibility 매핑
- 노출·클릭·완료 등 이벤트 수신
- 공급자 콜백 검증 및 무효 트래픽 처리
- 공급자 보고서·정산 자료 수집
- 오류·쿼터·정책 상태 관리

기존 ads.html에 Google IMA SDK 로더가 포함된 사실은 확인되었지만, 이는 실제 Google 광고 계정 연결, 유효 광고 인벤토리, API 자격증명 또는 수익 발생이 확인됐다는 뜻이 아니다. 기존 코드를 재사용하되 실연동 여부를 별도로 검증한다. 웹 광고와 모바일 앱 광고는 공급자 상품·정책에 따라 다르며, AdSense/Google Ad Manager/AdMob을 동일한 API로 취급하지 않는다.

### 7.3 공통 광고 모델
- AdSource: direct / network / affiliate
- Advertiser
- Campaign
- Creative
- Placement
- AdRequest
- Impression
- Click
- Completion / Engagement Event
- Provider Callback
- Invalid Traffic Review
- Provider Settlement Statement
- Internal Contribution Ledger Reference

### 7.4 경제적 분리
서로 다른 세 흐름을 분리한다.
1. 광고주 예산·청구·환불 및 직접 광고 매출
2. 외부 광고 공급자의 과금 이벤트·수익 배분·정산
3. TimeLink 이용자의 내부 기여 기록 및 승인된 TL/TLC/POC 처리

광고 완료 콜백 하나만으로 POC나 TLC를 지급하지 않는다. 공급자 정책, 유효 이벤트 검증, 중복 방지, 무효 트래픽, 정산 확정 및 별도 승인된 보상 규칙을 확인한다. 외부 광고 참여에 대한 인센티브는 공급자 약관이 허용하는 범위에서만 설계한다.

일반 사용자 광고 참여 화면, 광고주 센터, 관리자 전용 광고 연동 센터를 구분한다.

## 8. TL Economics 및 결제

TL Economics는 독립적인 13번째 제품 모듈이 아니라 플랫폼 전체에 적용되는 통합 경제 프레임워크다.

- TL: 시간 기반 내부 이용 단위
- TLC: 별도 규칙에 따른 기여 보상 자산
- POC: 기여의 측정·증명·판정 체계
- Payment: TL 충전 및 결제 처리
- Wallet: 잔액, 보유 자산, 거래 내역
- Creator Settlement: 권리자·창작자 정산
- Ad Settlement: 광고주·공급자·내부 정산
- Economy Ledger: 원장 및 감사 가능한 거래 이벤트

TL·TLC·POC를 같은 잔액이나 통화로 표시하지 않는다. TL의 환산·가격 정책, POC 가중치, TLC 발행·소각·전환, 보상 배분은 이미 승인된 규칙을 확인한 후 구현한다. 새로운 수치나 경제 정책을 UI 설계자가 임의로 정하지 않는다.

## 10. 기술 아키텍처 원칙

### 10.1 계층
1. Experience Layer: 공개 웹, 회원 UI, 모바일 반응형, 관리자 및 광고주 화면
2. Application Layer: SharePlace, Creator, Label, Track, Broadcast, DJ, Cafe, InCar, Ads
3. Shared Domain Services: Identity, Rights, Asset Registry, Social, Catalog, Notification
4. Time & Economy Core: Time Authorization, Usage Accounting, TL Economics, Payment, Wallet, Settlement
5. Integration Layer: Local Agent, external music/distributor APIs, ad provider adapters
6. Data & Storage Layer: 기존 D1, 기존 파일 저장 경로, 로컬 에이전트, 기존 데이터 및 로그

### 10.2 저장 위치 관련 주의
기존 문서 간 차이가 확인됨:
- 프런트엔드 PRINCIPLES: 원본은 로컬 PC, TL3 파일은 D1 object로 기술
- 백엔드 TL_PRINCIPLES: TL 파일 원본은 창작자 PC, 서버는 중계자, D1은 메타데이터로 기술
- 실제 Local Agent 및 API 구현도 함께 존재한다.

따라서 저장소의 단일 최종 정책을 이 문서만으로 임의 확정하지 않는다. 실제 구현과 운영 중인 접근 경로를 조사하고, 보안·가용성·비용·권리 원칙을 함께 평가한 별도 ADR(Architecture Decision Record)을 작성한다. 기존 데이터 이동, 삭제, R2 활성화, 저장 위치 변경은 승인 없이 수행하지 않는다.

### 10.3 기존 기술 재사용
- Cloudflare Workers/D1 API와 인증 체계를 우선 재사용한다.
- 기존 Local Agent 및 cloudflared 연결은 작동 경로를 보존하고 테스트한다.
- 기존 TLNK/TL3 형식, AES-GCM, 토큰 체인, 플레이어 로직은 시각 개편과 분리한다.
- timelink-score는 별도 확장 서비스로 유지하고 TL3 API 및 rights 메타데이터 계약을 검증한다.
- 새 UI는 기존 API 계약을 우선 사용한다. 결함이 입증된 경우에만 별도 변경안을 작성한다.
- 공통 디자인 시스템과 재사용 UI는 점진적으로 도입한다. 모든 페이지에 전역 사이드바나 공통 스크립트를 강제로 삽입하지 않는다.

## 11. 화면 및 UX 디자인 기준

- 프리미엄 디지털 창작 플랫폼: 짙은 네이비/차콜, 절제된 블루·바이올렛 포인트, 명확한 타이포그래피
- 데스크톱: 일관된 내비게이션, 상단 유틸리티, 넓은 콘텐츠 캔버스
- 모바일: 좁은 화면에 맞는 상단/하단/드로어 내비게이션
- TL3/TL4/TLD/TLJ는 유형별 카드와 상세 표현을 제공하되 공통 자산 정보 구조는 일관되게 유지
- Track Page는 소셜 상호작용과 홍보가 중심이며, 곡별 고유 URL을 갖는다.
- My Dashboard는 요약과 빠른 작업 중심, My Files는 파일 관리 중심으로 구분한다.
- 모든 화면은 로딩·빈 상태·오류·성공·권한 없음·재시도 상태를 제공한다.
- TL·TLC·POC는 시각적으로 명확히 구분한다.
- 기존 정상 동작을 확인하지 않은 채 버튼·경로·사용자 경험을 제거하지 않는다.

## 12. 기존 구현 자산의 통합 계획

기존 코드 인벤토리에서 우선 대조할 항목:
- index.html, login.html, signup.html
- dashboard.html, sidebar.js
- shareplace.html, track.html
- creator.html, creator-studio.html
- radio.html, cafe-radio.html, incar.html
- dj-center.html, cafe-channel.html, cafe-owner.html, incar-channel.html
- wallet.html, ads.html, advertiser.html
- TL3 player, Local Agent, API routes, D1 schema
- timelink-score pipeline 및 rights attribution

대조 분류:
- KEEP: 기능과 API가 정상이며 목표 구조에 부합
- INTEGRATE: 기존 기능은 유지하고 공통 기반 또는 새 화면에 연결
- ADAPT: 목표 정책과 충돌하는 부분을 제한된 변경으로 수정
- REBUILD UI ONLY: 기능/API는 유지하고 화면만 새로 구현
- NEW: 현재 없는 기능
- DEPRECATE AFTER MIGRATION: 대체와 데이터 보존 및 회귀 검증 후 단계적으로 종료

이미 확인된 주의점:
- Creator의 기존 업로드 흐름은 Local Agent 및 여러 API 호출에 의존한다. 신규 UI 검증 전까지 기존 경로를 보존한다.
- 구형 무료 MP3 공개 분기와 원본 URL 공유는 TL-only 배포 원칙과 충돌한다. 기존 기록은 감사·마이그레이션 대상으로 유지하되 새 공개 흐름에는 허용하지 않는다.
- dashboard.html과 wallet.html에 지갑 UI가 중복될 수 있다. 어느 화면을 기준으로 할지 API·동작을 비교한다.
- sidebar.js는 모든 페이지에 일관되게 적용되지 않는다. 페이지별 셸을 조사하고 단계적으로 통합한다.
- ads.html의 Google IMA SDK 로더는 실제 광고 네트워크 연결 증거가 아니다.
- track.html은 이미 좋아요·팔로우·플레이리스트·공유 및 TL3 관련 기능이 있다. 기존 기능을 확인해 곡별 소셜 페이지로 확장한다.

## 14. 개발 안전 규칙

1. 운영 브랜치에 직접 실험하지 않는다. 별도 feature branch에서 작업한다.
2. 한 번에 한 영역씩 변경한다.
3. 변경 전 파일·API·DB 의존성을 조사한다.
4. 기존 정상 기능을 보존하고 기능 변경과 UI 변경을 분리한다.
5. TypeScript/JavaScript 빌드·정적 검사·API 테스트·브라우저 흐름 검증을 수행한다.
6. TL 잔액, TLC, POC, 권리·소유 정보, 발행 파일, 저장 위치, 암호화 및 세션 규칙은 UI 작업에서 변경하지 않는다.
7. DB migration은 별도 설계·백업·롤백 계획과 명시적 승인 후 진행한다.
8. 비밀키·토큰·광고 자격증명을 소스 코드에 저장하지 않는다.
9. 배포는 사용자가 승인한 절차만 사용한다. 테스트 성공만으로 자동 운영 배포하지 않는다.
10. 완료 보고에는 변경 파일, 커밋, 테스트 결과, 미해결 사항 및 롤백 방법을 포함한다.

## 15. 완료 기준

- 공통 기반이 한 번 정의되고 각 서비스가 일관되게 사용한다.
- TL3/TL4/TLD/TLJ가 동등한 자산 유형으로 지원된다.
- 업로더 책임 선언, 외부 발매 이력 및 권리 증빙 수준이 구분된다.
- 원본 파일은 비공개 제작 자산으로 취급되고 공개 유통은 보호된 TL 자산으로 이루어진다.
- My Dashboard, My Files, My Assets, My Music의 역할이 명확하다.
- 곡별 Track Page에 좋아요·댓글·답글·공유·저장·팔로우·홍보·통계가 연결된다.
- TimeLink Label은 권리 취득자가 아니라 TL3 발행·관리·유통 지원 영역으로 구현된다.
- 직접 광고와 외부 광고 공급원은 공통 광고 엔진에서 관리되고 정산 흐름은 분리된다.
- TL Economics는 모든 서비스 활동과 연결되지만 무효·중복 이벤트가 보상으로 자동 반영되지 않는다.
- 기존 정상 기능, URL, 데이터 및 API가 검증된 상태로 보존된다.
- 데스크톱·모바일 및 오류·빈 상태가 검증된다.
- 운영 전환과 롤백 절차가 문서화된다.
